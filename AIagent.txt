### How the Agent Works

User clicks "Start Trade Day" → even if the user close broser or not → agent runs server-side all day independently.

State:
- trades_today = 0, max = 3
- Fetch daily_start_balance from Bybit on start
- Auto-shutdown scheduled at 6:00 PM Pakistan Standard Time (UTC+5)

---

### Coin Scanner — Phase 1: Hard Filters

Pull coin universe from user's coins list in mongo settings.
For each coin fetch from Binance Futures:
- 24h ticker (volume, price change)
- 4H candles (50) + 1H candles (50) + 5m candles (100)

Hard filters:
- 24h volume > $30M USDT
- ATR(14) on 5m within min/max threshold (configurable)
- 4H EMA20 vs EMA50 must show clear trend (not flat)
- 1H trend agrees with 4H trend
- RSI(14) on 5m < 38 for long candidates OR > 62 for short candidates
- No existing open position on this coin on Bybit

---

### Coin Scanner — Phase 2: AI Quality Scoring

For each candidate send to Kimi AI (moonshot-v1-8k) with:
- Symbol + direction bias
- 4H (last 30), 1H (last 30), 5m (last 50) candles
- RSI, MACD, ATR, Volume ratio vs 20-period avg
- Detected divergences
- Swing highs/lows as S/R levels
- HTF trend summary

Kimi must return ONLY valid JSON no markdown:
{
  "score": 0-100,
  "direction": "long" | "short",
  "entry": number,
  "sl": number,
  "tp1": number,
  "tp2": number,
  "rr": number,
  "confidence": "low" | "medium" | "high",
  "reasoning": "max 200 chars"
}

Only trade if score >= 75 AND confidence is "medium" or "high".
If multiple qualify, pick highest score.

---

### Trade Execution & Position Management

Place market order on Bybit with autopilot mode on: direction, base size, SL, TP from AI response. trades_today++.

Monitor position every 15 seconds after entry:
- Unrealized PnL hits -2% of account → force close
- TP1 hit → close full position
-AUTOPILOT MODE RULES(Already built and working)
- TP Direction: Price reaches 50% toward TP → SL moves to half initial risk  ·  Price reaches 60% toward TP → SL moves to entry (breakeven)
- SL Direction: Price drops 60% toward SL (without hitting TP milestones) → TP moves to entry (breakeven close)
- Position closes → send result notification → resume scan if trades_today < 3

---

### Scan Loop Logic

- No candidates → wait 30min → scan again
- Candidates found but all scores < 75 → wait 30min → scan again
- Trade just closed → wait 15min cooldown → scan again
- Active open position → skip scan, monitor only
- 6:00 PM PST → send daily summary → shutdown agent
- trades_today hits 3 → send daily summary → shutdown

Agent trades both longs and shorts.

---

### Guardrails (validate before every trade and every DCA, no exceptions)

- Max loss per trade: 1% of account → force close
- Max DCA: 2 additions, sizes 1.0x → 0.5x → 0.25x
- DCA only if RSI turning back in trade direction AND 4H trend still agrees
- Max exposure per direction: 6% of account
- Daily drawdown 5% → shutdown, no more trades
- Consecutive losses 3 → pause for the day
- Position in loss > 20 candles → force close
- 6:00 PM PST hard stop regardless of state

### Database Tables

CREATE TABLE IF NOT EXISTS agent_sessions (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id INTEGER NOT NULL,
  date TEXT NOT NULL,
  trades_taken INTEGER DEFAULT 0,
  wins INTEGER DEFAULT 0,
  losses INTEGER DEFAULT 0,
  total_pnl REAL DEFAULT 0,
  start_balance REAL,
  end_balance REAL,
  started_at TEXT,
  ended_at TEXT,
  end_reason TEXT
);

CREATE TABLE IF NOT EXISTS agent_trades (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id INTEGER NOT NULL,
  session_id INTEGER,
  symbol TEXT NOT NULL,
  side TEXT NOT NULL,
  entry_price REAL,
  close_price REAL,
  sl REAL,
  tp REAL,
  pnl REAL,
  pnl_percent REAL,
  ai_score INTEGER,
  ai_confidence TEXT,
  ai_reasoning TEXT,
  dca_count INTEGER DEFAULT 0,
  opened_at TEXT,
  closed_at TEXT
);
